# ۰۷ — تم روشن، تاریک و سیستم

[بازگشت به فهرست](../README.md)

## دو مفهوم مستقل

ترجیح ذخیره‌شده یکی از `light`، `dark` یا `system` است.
تم نهایی فقط `light` یا `dark` است. در حالت system، تم نهایی از تنظیم سیستم می‌آید؛
نباید به جای ترجیح system، نتیجهٔ فعلی را ذخیره کرد.
زبان کاربر و ترجیح تم دو تنظیم مستقل‌اند.

## توکن‌های معنایی

برای هر دو تم، زمینهٔ اصلی، سطح، سطح بالاتر، متن، متن کم‌رنگ، کادر، کنترل، primary،
متن روی primary، hover/active، وضعیت‌های success/warning/danger/info، فوکوس،
انتخاب متن، غیرفعال، overlay، skeleton، سایه و رنگ‌های نمودار صریح تعریف شده‌اند.
نام‌های دو مجموعه باید یکسان باشند. تاریک کردن با filter inversion یا وصلهٔ صفحه‌ای پذیرفته نیست.
رنگ‌های نمونه نقطهٔ شروع‌اند و در محصول واقعی باید اندازه‌گیری شوند.

## اسکریپت نمونه

[theme-bootstrap.js](../skills/bilingual-ui-system/assets/theme-bootstrap.js) یک نمونهٔ مرورگری است.
کلید ذخیره‌سازی آن `ui.theme.preference` است و API زیر را ارائه می‌کند:

```javascript
window.uiTheme.getPreference();
window.uiTheme.getResolved();
window.uiTheme.setPreference('light');
window.uiTheme.setPreference('dark');
window.uiTheme.setPreference('system');
```

پس از تغییر، رویداد `ui-theme-change` با preference و resolved ارسال می‌شود.
`destroy()` شنونده‌های رویداد و API نمونه را پاک می‌کند؛ مالک چرخهٔ عمر برنامه باید آن را درست مدیریت کند.
رویداد ابتدایی پیش از نصب شنوندهٔ برنامه ممکن است گذشته باشد؛ مقدار اولیه را از getter بخوانید.

نمونه، تغییر سیستم در حالت system، همگام‌سازی رویداد storage و خطای دسترسی به localStorage
را مدیریت می‌کند. انتخاب نامعتبر در setPreference خطا می‌دهد و مقدار ذخیره‌شدهٔ نامعتبر به system برمی‌گردد.
اگر ذخیره‌سازی بسته باشد، انتخاب در حافظه باقی می‌ماند و پایداری بعد از refresh تضمین نمی‌شود.

## SSR و نمایش اولیه

از روش موجود پروژه، کوکی سمت سرور یا bootstrap سازگار با CSP استفاده کنید.
نمونه را بدون تصمیم دربارهٔ SSR، hydration و CSP کپی نکنید و CSP را برای آن ضعیف نکنید.
اگر روش انتخابی به اجرای پیش از اولین paint نیاز دارد، زمان‌بندی بارگذاری باید آن را تأمین کند.
این اسکریپت زبان و جهت را حدس نمی‌زند؛ آن‌ها باید از مسیر/تنظیم زبان برنامه بیایند.
`color-scheme` باید با تم نهایی هماهنگ باشد تا کنترل‌های بومی هم درست نمایش داده شوند.

## بررسی ضروری

انتخاب صریح روشن/تاریک باید بر تغییر سیستم غالب باشد.
تغییر تم نباید دادهٔ فرم، زبان، فیلتر یا فوکوس را پاک کند.
Dialog، toast، tooltip، autofill، جدول، نمودار و حالت disabled را در هر دو زبان بررسی کنید.
